### Fixed

- `n4_rollback` / `n4_remove_component` (#200, B1200-G3): a struct type is a slot value, not a component. `alarm:LimitEnable` (a `baja:Struct` by the station registry) was classified as a component by the naming rule (every type outside `baja`), so a rollback split it out, reported it in `frozen_config_not_restored` as `missing`, and an out-of-range alarm came back with `highLimitEnable` / `lowLimitEnable` false (disabled). The rollback now classifies a type by the supertype chain the registry describes (a component reaches `baja:Component`; a described chain that does not is a value), keeps the static table first and the naming rule as the fallback for a type the registry does not describe, and the rollback plan notes which types the naming rule decided. The remove snapshot counts a struct as part of the body of the component holding it (`SnapshotDepth` is unchanged and counts component levels), so a struct's slots below the depth cut are captured, written back, and no longer listed in `snapshot_truncated`. A client without a registry channel behaves as before. A struct on the last level the snapshot loads has children that were never read, so `snapshot_truncated` lists it instead of showing a complete snapshot.
