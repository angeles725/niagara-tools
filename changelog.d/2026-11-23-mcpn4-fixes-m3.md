### Added — mcp-n4 warns on an unexplained empty read, checks copy capacity and handles history ids on rename

- `n4_read_history` and `n4_read_audit`: a filtered read that returns no rows while its `count(*)` also fails now
  carries `warning` ("the filter may name no field"). Before, the only hint was `total_records_note`.
- `n4_copy_component` and `n4_replicate_points` refuse, at the dry run, copies that would take the devices
  (`driver:Device`) or proxy points (`driver:ProxyExt`) over the licence `device.limit` / `point.limit`, as
  `n4_create_component` already did for a device. A licence that cannot be read leaves the plan unchanged.
- `n4_rename_component` lists, in the plan notes, the history extensions whose id changes with the rename (old and
  new id). The new optional `freeze_history_names` sets each `historyName` to its current text in the same batch,
  before the renames, so trends do not split. The test station now answers the `RenameOp`.
- Not done: the `ping` read-back (#931) stays `unverified`.
