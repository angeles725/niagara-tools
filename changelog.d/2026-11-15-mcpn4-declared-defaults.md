### Fixed — mcp-n4: reads list declared properties still at their default, and a rollback to a default reads verified
- A BOX load leaves out a frozen property still at its type default, so a fresh component read `slots: []`. `n4_read_slots` now lists those properties after the loaded slots, and `n4_navigate` under each component whose children it lists, from the type contract of the station's registry (`loadTypes`, read once per session for the listed types and their supertypes): each is marked `default: true` with the contract's default value, or `value: null` and a `note` when the contract gives no default value (a component default such as `proxyExt`). `defaults_note` says when a contract could not be read. No value is ever invented.
- The `n4_rollback` read-back counts a frozen property the load leaves out as its declared default, so restoring a default reads `verified` instead of `mismatch`.
- A type the station does not describe (an error entry, or left out of the reply) is asked for once per session too. `n4_navigate` lists the declared defaults under each component or struct slot whose children it lists; the sub-entries of a declared struct default may show `type: null`.
