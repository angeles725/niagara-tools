### Changed — mcp-n4 removes a creation chain in one step and can summarise a remove's snapshot

- `n4_rollback` takes `chain` (issue #930, optional, default false). On a create batch that later batches wrote
  under, `chain: true` plans the remove of the created component with those batches, under one token; the plan
  note `chain: removes the created <ord> with the later batch(es) under it, newest first: <id> (<tool>), ...`
  names them. It still refuses a later batch that also wrote outside the component (`batch <id> (<tool>) also
  wrote <ord>, outside <ord>: roll it back first, ...`) and a child or link no batch made. The later batches are
  not rolled back one by one: they stay in the journal as they were. Without `chain` the refusal is the same
  text plus `; n4_rollback chain=true removes it with the later batches in one step`. On a batch that is not a
  create, `chain` changes nothing and a note says so.
- `n4_remove_component` takes `compact` (issue #930, optional, default false). With `compact: true` the dry run
  replies `plan.inverse_summary` (`components`, `links_inside`, `unlinked_inputs`, `outgoing_links`, `inverse_ops`)
  instead of the whole snapshot in `plan.inverse`. `plan_hash`, the token and the journaled inverse are the same.
- Not done: `n4_list_templates` (#933), the composite `n4_register_bacnet_spyder` (#932) and `n4_apply` (#934).
  They need a deployed template instance and the station's template service read on a live station (BTemplateInfo
  slot names, the instance layout after a Workbench deploy, the propagation of `templateConfig`), and for #932 a
  plan that can follow an objectId the station assigns between steps.
