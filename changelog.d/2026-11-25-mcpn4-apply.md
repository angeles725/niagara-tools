### Added

- mcp-n4: `n4_apply(parent_ord, golden, rows)` copies a golden deployed template instance once per row of a table (`{name, configs}`, 1 to 30 rows) and sets each row's configs on the copy's `templateConfig`, in one batch under one confirmation token. A plain copy keeps each `ConfigBinding` `targetOrd` as the golden's handle (`h:758`), so setting a config on it would change the golden: the plan rewrites every binding of each copy to the slot ORD of its own target, then sets the configs with explicit ops (the station propagates a config only outside the decoding of an add). The read-back checks each copy, its bindings, each config and its target, and reports `golden_unchanged`. (#934)

### Changed

- mcp-n4: `n4_set_slot` on a `templateConfig` follows a `ConfigBinding` whose `targetOrd` is a slot ORD inside the instance (as `n4_apply` leaves its copies), not only a handle; a slot ORD outside the instance is refused like an unknown handle. (#934)
