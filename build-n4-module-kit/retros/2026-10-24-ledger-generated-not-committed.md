## What happened
`ledger.d/*.md`, `retros/*.md` and the new `BUILD-STATE.src.md` are now the only committed sources of the kit's
continuity state. `BUILD-STATE.md` and `retros/INDEX.md` are generated by `toolbelt/kit-state.sh` and `.gitignore`d,
so two PRs that each add a ledger fragment and a retro merge with a plain `git merge`.

- **The ledger-conflict tax (measured this round).** Landing kit PRs on 2026-10-23/24, one session needed extra
  `git merge origin/main` runs: #361 1, #376 2 (+1 merge GitHub refused after green CI because main moved), #366 2,
  #389 1, #391 1, #392 2 (+1 refused). That is 9 extra merges and 2 refused merges over 6 PRs. Every conflict was in
  `BUILD-STATE.md` and/or `retros/INDEX.md`, apart from 1 in `go/README.md` and 1 in `rules.go`, which were real
  content. GitHub's mergeability ignores local merge drivers, so `.gitattributes merge=union` could not help; it is removed.
- **Condition 3 split: a committed source file, a fully generated output.** The hand-written part moved to
  `BUILD-STATE.src.md`, and `BUILD-STATE.md` became fully generated and ignored. This is the shape the renderer already
  reads: `buildstate.Render(state, frags)` takes the whole file as its template and replaces only the kit envelope's
  `last_change` line, its `open_issues` items and the log after `last_session`. The source is exactly
  `Render(source, nil)`, so `--check` refuses a source that carries generated content (GBS-source) instead of
  dropping it silently. A `ledger.d/0000-*` header fragment would have needed a second parser for module envelopes.
  The alternative (keep a committed `BUILD-STATE.md` with empty generated parts) failed condition 2: `install-skill.sh`
  installs only the launcher, which reads `$KIT/BUILD-STATE.md` straight from the checkout. Generating there would
  dirty a tracked file. With the output ignored, generating into the checkout is always safe.
- **One reader command.** `go/internal/kitstate` (no rendering of its own) prints `build-state` / `retro-index`, or
  `--write`s both after generating both, so a violation writes nothing. Every reader doc and the launcher point at it,
  pinned by `tests/kit-state.bats` KS6/KS7.
- **Freshness everywhere.** `install-skill.sh` materializes the kit it resolves. `.githooks/post-merge`,
  `post-checkout` and `post-rewrite` (activated by `install-hooks.sh`) regenerate after every pull, checkout and
  rewrite. They exit 0 always; on a failure they print one warning line and delete both files, so no stale copy is left.
- **The lint index joined later.** `toolbelt/INDEX.md` (fully generated from the lint headers) caused another
  land conflict, so it follows the same model: `kit-state lint-index`, ignored, `gen-lint-index --check`
  validates headers, and LM3 shows two lint-adding branches merging cleanly. The generators' shared
  compare-with-committed code (`gen.File.Run`/`check`) had no caller left and was removed.
- **Gates read generated output.** `gen-* --check` validates the inputs (fail closed). `sweep-build-state` compares a
  GENERATED file wherever it lives, and CI and pre-push sweep fresh kit-state output from a temp dir. The pre-push
  promotion anchor is now a retro header flip `pending` → `folded`. The stale `last_session:` head (2026-10-16) moved
  into the archive fragment as a log line.

## Lessons
- A merge driver is not a fix for a conflict on GitHub. The only robust fix for a derived file is to stop committing it
  and to regenerate it wherever it is read (install, pull hook, CI temp dir).
- Before choosing where generated output lives, check how the reader gets the kit. Here the launcher reads the
  checkout, so condition 2's premise ("the installed copy ships the files") was false and changed the split.
