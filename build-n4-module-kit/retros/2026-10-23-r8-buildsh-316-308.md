## What happened
The RDD review of the mirror user.home guard (`fix/r8-mirror-userhome`) spent its one-correction budget and filed
#316: the dev-key WARN fired only on the build that created the mirror signing profile, so every later build of a
root without the signing block signed with the same throwaway key in silence; and `$HOME` reached
`JAVA_TOOL_OPTIONS` unquoted as `-Dmaven.repo.local=$HOME/.m2/repository`, so a `$HOME` with whitespace was split
by the JVM exactly like the mirror path the exit-33 guard already refused. Separately, #308 found that `build.sh`
could not forward `-P` gradle properties, so the property-driven signing block could only be fed through
`ORG_GRADLE_PROJECT_*` environment variables.

## Lessons
- A state file that persists across runs cannot tell "created this run" from "created by an earlier run of the same tool"; when every such file is tool-created, warn on its presence, not on its creation.
- Every value appended to `JAVA_TOOL_OPTIONS` is split on whitespace by the JVM, so each one needs the same whitespace guard, not only the first one reviewed.
- A build driver that builds its own gradle command line needs an explicit property passthrough; environment-only routes (`ORG_GRADLE_PROJECT_*`) are easy to miss.
