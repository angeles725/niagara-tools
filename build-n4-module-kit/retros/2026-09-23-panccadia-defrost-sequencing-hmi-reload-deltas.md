# 2026-09-23 · kit · panccadia-defrost-sequencing-hmi-reload-deltas

**Session**: PANCCADIA field support (JACE-9000, 4.15.3.28). This is an applied change over the operator's three client modules in `C:\Users\equipo\Downloads\niagara-panccadia-leon` (git-initialized this session, baseline `116c49a`, branch `feat/defrost-sequencing-hmi-reload`). Changes: CompPan 2.1.0→2.1.1 (redeploy the debounce), DashboardPan 2.4.2→2.4.3 (the HMI auto-recovers), ColdRoomPan 2.1.2→2.1.3 (room-level defrost sequencing, duration/interval anchors, manual HOA precedence).

**Delta count**: 6 (draft; may grow)

## What happened
1. **The HMI goes blank after a station restart.** The 10" Honeywell kiosk loads `/dashboardpan/`. The SPA's `poll()` (`setInterval(poll, 5000)`) only marks data stale on error and never reloads. After a station restart the web session is dead, so the kiosk shows no values until someone power-cycles it. The kiosk browser settings have no page-level auto-refresh, so the SPA has to own the recovery.
2. **The fix never reached the JACE.** CompPan's `changed()` debounce was built on 2026-09-21 in `leon`, but the JACE last received modules on 2026-09-07 (`leon2`). Both trees declare `2.1.0`, so Software Manager reports "Up to Date" and will not install the fix. The operator also had two source trees with identical versions and no record of which one was deployed.
3. **The operator requested manual precedence.** A deliberate code rule (`BEvaporatorUnit.setBool`, comment "their HOA never overrides defrost") meant an engineer could not switch an evaporator fan OFF during an air defrost. The operator had started working around it with kitControl Equal/Not/And/Or blocks on the wire sheet. That field workaround is a signal that the module's precedence contract was wrong for the user.
4. **Per-unit refactor made the coordination inert.** PR1c moved `BDefrostController` under each `BEvaporatorUnit`. `units()` then returns a single element, so the token/queue/`staggerDelay` machinery never engages, and a room with two electric resistances can defrost both at once. The code comment admitted "inert" but nothing flagged it.
5. **Cycle timers were anchored at the wrong moments.** The interval re-arms at defrost START (`doIntervalExpired`, `requestDefrostCycle` stamps `lastDefrostTime` at start). The duration ticket is armed before actuation (`beginDefrost` arms `durationTicket` before `doDefrostFanOffExpired` energizes the resistance). The customer's contract is duration-from-actuation and interval-from-end.

## Lessons (so far)
- A field workaround (wire-sheet logic that bypasses a module's rule) is a requirements signal. Capture it as a contract change instead of documenting the workaround.
- "Built" is not "deployed". Without a version bump and a deployed-baseline record, a verified fix can sit on disk for days while the station keeps failing.
