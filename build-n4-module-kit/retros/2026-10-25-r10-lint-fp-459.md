## What happened
The issue body lists nine false-positive bullets from a client sweep. Each one was checked against origin/main
before any code changed. Eight were already fixed, in whole or in part:

- #464: catch-no-400 re-read fallback, silent-protection, null-context-write own-child seeding,
  bql-string-concat numeric-only.
- #474: arbitrary-ord, both the guarded constant-prefixed ord and the `BAlarmRecord.getSource()` ord.
- #483: rc-scan innerhtml-server (page-owned literals), disabled-gate (a stated non-gate reason) and vendored
  `rc/vendor/**/*.js`, which is now left to lint-vendor-floor (the bulk of the null-branch / browser-floor
  rows). The browser-floor-under-`--profile unknown` half of that bullet was not re-checked here.

The ninth bullet, rc-scan host-literal, is still open.

The issue comments add more shapes. One of them was fixed here:

1. cache-nofinger, `?v=`-conditioned max-age. A servlet that sends `max-age>0` only on a request that carries the
   fingerprint query parameter (`fingerprinted ? "public, max-age=3600" : "no-cache"`, with every call passing
   `req.getParameter("v") != null`) was flagged. It went RED in a new golden
   (`truth-cache-fingerprint-1.txt`, rows at 7, 12 and 18). Then it went GREEN: every max-age literal on the line
   must be the then-branch of a ternary whose condition is a fingerprint test (`getParameter("v"|"ver"|"version")
   != null`, with no `||` and no `?:`), or a boolean parameter of the private enclosing method that every call of
   that name passes such a test. Ten true-positive neighbours stay WARN, and each of the nine mutations of the
   new helper turns the golden red.

The other three were not changed:

- cache-nofinger, build-time token. The servlet sends max-age to every non-HTML request whatever its query; a
  gradle filter puts a `__BUILD_ID__` token into index.html and js. The servlet alone does not prove that a request
  carries the token: an asset referenced from CSS, or a URL typed by hand, is cached for the full max-age. The row
  stays. The fix belongs in the module: send max-age only to a request that carries the token, the shape now
  accepted.
- catch-no-400, upstream finite guard. The swallow `catch (NumberFormatException e) { return 0.0; }` sits in a
  private helper that is reached through a second private method. The caller validates the value (400 on a
  non-finite value) only for the numeric slot types, and the helper is used only for those types. The default is
  dead today, but it is a latent silent default: one new caller without the guard writes 0. The rule is per
  catch, and this exact helper shape was already pinned to WARN in `truth-catch-reread-1.txt` (line 10). This is
  a true positive under the rule's contract. The fix is in the module: let the helper throw, or pass it the
  validated double.
- rc-scan host-literal (a literal URL in an unselected config mode), browser-floor under `--profile unknown`, and
  the slot-coverage per-slot "OPERATOR" comment. These live in `go/internal/rcscan` and `go/internal/slotcoverage`,
  which were outside this session's edit surface. They were reported, not changed.

## Lessons
- An issue checklist goes stale fast when several sessions fix it in parallel. Eight of the nine bullets had
  been fixed, in whole or in part, by three merged PRs, so `git log origin/main --grep '#<issue>'` came before writing any
  RED test.
- A line-based ternary reader has to handle `==` as one operator. Read as two `=` tokens, it cut the condition
  short, so the `!` of `!= null` was not pinned until a `== null` neighbour was added.

## Owed
- The rc-scan host-literal and browser-floor shapes, and the slot-coverage OPERATOR comment shape, need a session
  whose edit surface includes `go/internal/rcscan` and `go/internal/slotcoverage`.
