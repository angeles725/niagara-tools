## What happened

kit says `niagaraTest` finds 0 tests from WSL (plugin 7.6.17 bug) and sends station tests to Workbench → Tools → Run Tests
(`types/moduleTest.md:10-13,156,385-386`, `BUILD-LOOP.md:162-165`). In the N4 developer course the user had run
`niagaraTest` natively on Windows (Lab 7: 9/9 passed). This session wrote `BCompressorCallStationTest extends BTestNgStation`
(a real `BColdRoom` with two real `BEvaporatorUnit` children in the test station, driven only through `coilTemp`/`valveMode`)
and ran it with `cmd.exe /c gradlew.bat ... :ColdRoomPan-rt:niagaraTest` from WSL against PowerB 4.15.3.28. It passed 6/6
after three environment fixes, and each of five named production mutations made 1-3 tests fail. Two of the failed attempts
ended in `BUILD SUCCESSFUL` with zero tests run. That silent pass is a bigger risk than the WSL limitation the kit
documents.

## Lessons
- A test task that can exit green with zero tests is not a gate. Parse the test count and require N>0.
- A rule written as "X cannot run here" needs the exact environment that failed (OS, plugin version). Without it, one environment's failure turns into a general rule and hides a route that works.
- Station tests drive real slots. Each mutation here failed a test through runtime behaviour, which a source-text test cannot show.
- Running Gradle against a niagara_home writes into its `modules/`. Back up before the run and restore after it.
