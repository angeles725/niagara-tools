# 2026-09-19 · kit · apillm-headless-servlet-rt-4.14-deltas

**Session**: Apillm client module (Cliente/LLM/Apillm) — headless no-Workbench build of an rt+wb read-only JSON gateway servlet on N4.14.0.162; scaffold→build→sign→verify proven from WSL.
**Delta count**: 24

## What happened
Building a BWebServlet-based gateway where the servlet lives in the **-rt** profile (not -ux), the
`--type dashboard` scaffold and the current per-type guidance produced three reproducible build
breaks and one verify WARN. Root-caused each against the 4.14 install jars (javap) and fixed them in
the client module; proposing the fixture/doc deltas so the next servlet-in-rt build is green first try.

## Evidence
- `BMinimalDash`/`BApillmServlet` (dashboard fixture) `@Override public void doService(WebOp)` fails
  to compile: `javap javax/baja/web/BWebServlet.class` (4.14 web-rt.jar) shows `doService` is
  `private(HttpServletRequest,HttpServletResponse)`; overridable dispatch = `service/doGet/doPost/doPut/doDelete(WebOp)` + `getServletName()`. Fixture also hardcodes `getServletName()="minimaldash"`. `[ev: javap BWebServlet 4.14]`
- rt `compileJava` fails on `javax.servlet.http.*` unresolved until `compileOnly("javax.servlet:javax.servlet-api:3.1.0")` added to the rt gradle — the ux scaffold gets it transitively, the rt profile does not. `[ev: Cliente/LLM/Apillm/Apillm/Apillm-rt.gradle.kts]`
- wb subproject cannot resolve `:baja`/`:web` until `id("com.tridium.convention.niagara-home-repositories")` is in the wb `gradle.kts` (rt has it; chihuahua-wb relies on it). `[ev: chihuahua-wb.gradle.kts]`
- `verify-module.sh` `palette-root` WARN: scaffold emits root `t="b:Folder"` (access-controlled); B746 §746.1 wants `t="b:UnrestrictedFolder"`. `[ev: corpus B746]`
- wb agent only registered when `<agent>` block is in `module-include.xml` AND `@AgentOn` is inline in `@NiagaraType`; inline-only did not emit it. `[ev: Cliente/LLM/Apillm/Apillm/Apillm-wb/module-include.xml]`

## Lessons
- A BWebServlet in -rt is a first-class shape; the scaffold assumes -ux and silently drops the servlet API + palette hygiene there.
- Root-cause servlet override errors with `javap` of the target-version's `BWebServlet`, never from memory — the overridable set is `service/doGet/doPost/doPut/doDelete(WebOp)`, not `doService(WebOp)`.
- `verify-module` + `lint-servlet` + `lint-structure` all green from WSL prove module creation needs no Workbench — only the SDK + signing cert from the install.
- **USER RULE (standing): user-facing module UI must be intuitive and easy** — pickers/choosers + drag-drop + status tables, never a blank-entry "Add" that dumps the user into the raw property sheet. Applies to every `-wb`/`-ux` build going forward, not just Apillm.
