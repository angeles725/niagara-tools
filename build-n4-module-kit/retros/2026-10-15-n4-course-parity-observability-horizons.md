## What happened
After the topic retros, four cross-cutting gaps remained. (1) The kit has no callback thread map: which thread runs
`started()`/`stopped()`/`changed()`/`checkAdd()` (B1238 §1238.2; kit grep `Nre:Console`/`main thread` → 0). (2) The Slide
Code's `BPair.encodeToString()` formats through `toString()` — locale-dependent display formatting — so on a decimal-comma
locale (our stations run Spanish) a BOG save/load corrupts the value; the kit's value-type guide does not warn about it
(`types/value-types.md:123-144`). (3) A parity read of our three production modules against the course found four places
where the course convention is better and two where ours is better. (4) The visual blocks record observability facts the kit
lacks (Resource Manager engine statistics, FINE not reaching LogHistory, the permission-error chain, the missing
`MANAGE_EXECUTION` shutdown symptom, the lexicon diagnostics switch, history-extension defaults). The user also asked for a
"horizons" list: course capabilities our kit and modules do not exploit yet.

## Lessons
- Our production modules already beat the course on testability and timer discipline, and trail it on lexicon keys, palette roots and logger naming; parity reads cut both ways.
- Display formatting is locale-dependent; persistence encoding must never go through it, especially on Spanish-locale stations.
- The engine, the console, the Fox dispatchers and the bootstrap thread all touch the same component; a thread map belongs next to the callback list.
