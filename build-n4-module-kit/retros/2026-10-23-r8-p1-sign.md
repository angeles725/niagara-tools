## What happened
While folding the program-object signing rule (pps Δ7) the kit's BProgram section turned out to say an unsigned
`BRobotCode` blob "is rejected at instantiation". `BCode` verifies only when a signature is present or the
`program.requireSigning` system property is true; otherwise it logs a WARNING and loads. The guide says the code
"must be signed" and, three lines later, that enforcement is off by default. The kit had kept the "must" and
invented the consequence.

## Evidence
- vineflower program-rt 4.14.0.162 `com/tridium/program/BCode.java:202-215` (`checkSigning = signature.length() > 0 || Boolean.getBoolean("program.requireSigning")`; else `log.warning(program.notSigned)`), `:254-268` (a failed verification throws)
- `niagara-help/versions/4.15.6.20/guides-clean/User/ProgramObjectSigning-10F25D1D.txt:7,16` `[ev: corpus B1332 §1332.2]`

## Lessons
- "Must be signed" and "is refused unsigned" are different claims; only the code says which one holds.
- A guide page can contradict itself (default Low vs Medium from 4.9); read the code path that picks the value.
