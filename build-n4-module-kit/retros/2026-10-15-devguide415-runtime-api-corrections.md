**Session**: research-sdd focus `dev-capabilities-kit-gaps` (niagara-research B1304–B1315) mapped the N4.15.6.20 Developer Guide + `javax.baja`/kitControl source against this kit; this retro carries the runtime-API corrections from corpus B1304 (threads/jobs), B1309 (links), B1310 (facets/formats/cursors) and B1314 (status). **Delta count**: 10

## What happened
Several kit cards name APIs that do not exist in the N4 source or describe real ones wrongly, so code written from them does not compile or misbehaves: `BWorker.post(Runnable)/postAsync()` (no such methods), `BJobs.submit` (no such class), `BFacets.makeDouble` and ~17 facet keys that are not `BFacets` constants, a `BStatus.and()` method, a BStatus bit table shifted by one bit from STALE onward with ALARM missing, a BFormat card that gets `?`, `time()` and `substring` wrong, a `doCheckLink` claim that programmatic links are checked, and a `new BLink(BOrd,…, true)` comment that calls the `enabled` flag "INDIRECT". The corpus blocks the kit cites are mostly right (B736 has the right bits, B1106 has no invented keys): the errors entered at kit transcription. The devguide also documents real capabilities the kit lacks: `ExecutorUtil` named executors, `BRunnableJob`, the `clockChanged` contract for absolute schedules, `activeLevel`, `minActiveTime/minInactiveTime`, and the alarm extension's ownership of the FAULT bit.

## Lessons
- Every API a kit card names should be grep-resolvable in the source tree; nine of these defects would have failed a "does this symbol exist" check.
- The cited corpus blocks were right where the kit was wrong — the transcription step needs the same source check as a block.
- Mechanism tables (bit values, key lists) belong in generated or test-pinned form, not hand-copied prose.
