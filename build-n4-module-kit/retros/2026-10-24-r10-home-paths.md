## What happened
The public kit hardcoded one user's home directory in live code: `toolbelt/orient-guard.sh` (the default
legal build prefix), `tests/lib/client-root.bash` (the default client read root) and one lint test fixture. The
guard now derives its default from `$HOME` (`$HOME/modulos_niagara_n4/Cliente/`), so it behaves the same for
the original user and works for anyone else; an unset or empty `HOME` with no test seam is an env error (exit 3)
instead of the root-level prefix `/modulos_niagara_n4/Cliente/`. The test seam `BUILD_N4_LEGAL_ROOT_PREFIX`
still wins and still prints its WARN row. `client-root.bash` defaults from `$HOME` too (an env override still
wins), and the machine-default-path fixture uses a neutral user. This is forward-only: no history or dated
record was rewritten.
