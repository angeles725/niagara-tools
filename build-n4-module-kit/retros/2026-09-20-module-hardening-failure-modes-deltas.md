**Delta count**: 16

## What happened
Sixteen failure-mode blocks completed the hardening sub-series covering runtime, persistence, build, and UX failure modes. The kit documents none of these failure modes directly: it has rt authoring rules for timers and changed() but no lifecycle contract, subscriber-symmetry rule, RBAC-safe post() note, or job-submission guidance; it has build prerequisites but no bytecode-version lint, split-package rule, Slotomatic expression triage, or runtimeProfile enum reference; it has deployment guidance but no silent-link-degradation watchdog pattern, wb-profile cross-target safety note, BConversionLink stale-converter rule, or restore-direction note. The UXS6 JS toolchain reference is the missing companion to UXS2 (ES5/ES6 decision). Seven of the sixteen deltas introduce lint candidates; four are SECURITY or SILENT-CORRUPTION priority.

## Evidence
- B1113 (RUN1): framework wraps executeExtensions per extension; changed()/timer/lifecycle callbacks are BARE — already deltaed as PD-MH-RUN1/Δ8 in module-hardening-reference-cards-deltas. Referenced here for completeness; no new delta. `[ev: corpus B1113]`
- B1114 (RUN2): changed() dispatch is SYNCHRONOUS direct-call on the same stack — an unconditional slot write from inside changed() calls changed() again immediately, producing StackOverflowError (not a queue flood); `fireDirectCallbacks()==false` prevents this on offline .bog. Deadband is the required guard, not just efficiency. `[ev: corpus B1114]`
- B1121 (RUN3): full lifecycle callback contract: started()/stopped() pair enable/disable and mount/unmount transitions; save does NOT fire stopped()/started(); started() runs on every enable cycle, so it must be idempotent; arm timers in started() only (one place); tear them in stopped(). `[ev: corpus B1121]`
- B1122 (RUN4): subscribe() in started() holds a bidirectional reference to the watched component — without a matching unsubscribe() in stopped() the watched component cannot be GC'd, the handler keeps firing after the subscriber is removed, and enable cycles stack duplicate subscriptions. Use lease() for transient reads; BLink self-manages its subscription. `[ev: corpus B1122]`
- B1129 (RUN6): invoke(action, arg, context) enforces permission via checkInvoke on the context's user (operator = bit 4, admin = bit 64); a null context skips the check (system-privileged). post() DROPS the caller's context entirely — the enqueued dispatch has no RBAC enforcement. Security rule: check permission yourself before post(). `[ev: corpus B1129]`
- B1130 (RUN7): BJobs submit on a ForkJoinPool (sized availableProcessors × niagara.job.threadsPerCPU); submit() is itself an action-invoke (RUN6 applies); a saturated or shutting-down pool throws RejectedExecutionException as an unhandled RuntimeException into the calling callback (RUN1 bare-callback death). `[ev: corpus B1130]`
- B1115 (PER2): an unresolvable link sourceOrd throws UnresolvedException, the knob is never installed, the target keeps its stale value, and NO fault or alarm is raised on the target side; cross-station links re-resolve only if the source mounts at that ORD. `[ev: corpus B1115]`
- B1116 (PER3): a component typed to a wb-profile module in a .bog decoded on an rt station is SKIPPED (element dropped, FINE log) or fails the whole load with failFast — it is NOT stubbed by BOnMissingType. `[ev: corpus B1116]`
- B1131 (PER5): BConversionLink persists its converter as a slot chosen once at link-creation; when the source type later changes, propagate() applies the stale converter with no try/catch — result is SEVERE-abort (throwing converter) or a silently wrong value (coercing converter). `[ev: corpus B1131]`
- B1123 (PER6): verifyDependencies is a FLOOR check (installed version ≥ manifest minimum); an older .dist restores onto a newer station; a newer .dist onto an older station fails; ignoreDependencies bypasses it. `[ev: corpus B1123]`
- B1117 (BLD1): a signature failure surfaces as ClassNotFoundException in userland, but the ROOT log entry is a ValidationException — "No code signers found" = the jar is unsigned; "Error validating cert path" = the signer cert is not trusted. Compare moduleVerificationMode across stations to rule out the skip path. `[ev: corpus B1117]`
- B1124 (BLD2): a class compiled at Java 9+ (major ≥ 53) throws a RAW UnsupportedClassVersionError — N4's ModuleClassLoader does not wrap it; it is a LinkageError (not Exception), so catch(Exception) does not catch it. Applies to bundled ext-jars, not just own classes. `[ev: corpus B1124]`
- B1125 (BLD3): N4 is NOT OSGi — split-package resolution is first-dependency-wins (declaration order, lastModuleScanned cache); a class in the same Java package in a second module is SILENTLY SHADOWED with no error or warning. `[ev: corpus B1125]`
- B1126 (BLD4): Slotomatic emits @NiagaraProperty defaultValue and flags as verbatim Java expression strings into the AUTO region without evaluating them; a bad-type defaultValue or a mistyped flag surfaces as a javac error on the GENERATED file — the annotation is the root cause, not the generated code. `[ev: corpus B1126]`
- B1127 (BLD5): runtimeProfile in module.xml is a Java enum — valid values are exactly {rt, ux, wb, se, doc}, case-sensitive; an invalid value causes RuntimeProfile.valueOf to throw IllegalArgumentException, which the manifest parser swallows into BModuleStatus.corrupt with the typo cause hidden in the log. `[ev: corpus B1127]`
- B1128 (BLD6): a `<type>` in module-include.xml whose class has no @NiagaraType annotation (and thus no generated `TYPE = Sys.loadType()`) is caught at registry-build time with SEVERE "Missing Sys.loadType()" — a named, non-silent error, not an NPE. `[ev: corpus B1128]`
- B1132 (UXS6): the -ux JS toolchain is grunt-niagara (Grunt task library) + the Gradle niagara-grunt plugin (wires gruntBuild → babel:dist/copy:dist/requirejs tasks); modules are loaded via RequireJS/AMD using `nmodule/<module>/rc/<path>` IDs; raw rc/ without this toolchain = ES5 is mandatory (pairs with UXS2/B1119). `[ev: corpus B1132]`

## Lessons
- **SECURITY (1):** Δ4 (PD-MH-RUN6, post()-drops-context) is the HIGHEST-PRIORITY actionable delta — using post() for a privileged action silently bypasses RBAC; there is no compile-time or runtime warning when the caller's context is dropped; this matches the null-context pattern from B829/B830 and the servlet RBAC gap from B1120.
- **SILENT-CORRUPTION (4):** Δ1 (RUN2 changed()-feedback → StackOverflowError with no log until the crash), Δ6 (PER2 dangling-link = stale value, no fault, no alarm — the hardest failure to detect in a live station), Δ7 (PER3 wb-type component silently dropped on rt), Δ8 (PER5 conversion stale after retype = wrong value with no error). All four rot state or silently produce wrong outputs with no signal.
- **RESOURCE-LEAK (2):** Δ3 (RUN4 subscriber — leaks the watched component AND keeps firing after removal; the lint candidate `subscribe-without-unsubscribe` is the most actionable addition here), Δ5 (RUN7 job flood → RejectedExecutionException propagates into a bare callback, killing the callback silently via the RUN1 mechanism).
- **LIFECYCLE (1):** Δ2 (RUN3 callback contract) clarifies that save ≠ stop/start and that started() is re-entrant across enable cycles — the most common source of duplicate-timer and duplicate-subscription bugs in our modules.
- **BUILD-TRIAGE (6):** Δ10–Δ15 are a BUILD-TRIAGE cluster; Δ11 (BLD2, bytecode UnsupportedClassVersionError bypasses catch(Exception)) and Δ14 (BLD5, runtimeProfile.corrupt hidden cause) are the least-obvious failures. Δ12 (BLD3, split-package) and Δ11 warrant lint candidates. Δ13 (BLD4 Slotomatic verbatim) and Δ15 (BLD6 @NiagaraType required) are documentation-only.
- **UX-TOOLCHAIN (1):** Δ16 (UXS6) closes the -ux documentation gap — without this reference, a developer building a -ux module with ES6 must discover the grunt-niagara + Gradle plugin wiring from source.
- Highest-priority flagged: **Δ4** (SECURITY), **Δ6** (SILENT-CORRUPTION, hardest to detect), **Δ3** (RESOURCE-LEAK, subscriber leak fires after removal), **Δ11** (BUILD, UnsupportedClassVersionError bypasses defensive catches).
