## What happened
Five parked "requires-execution" hardening gaps turned out to be code-investigable from the decompiled framework (`web-rt`, `jetty-rt`, `driver-rt`, `baja`) plus the install's Gradle signing plugin (`niagara-plugins-7.6.17.jar`, javap-corroborated). The kit documents none of these directly: it has servlet security guidance but no statement that the security-header filter is applied globally to every servlet context; no CORS recipe; no signing-profile-type build-triage note; no driver configFatal/configFail recovery reference; and no dynamic-slot orphan-prune rule. Three deltas are SECURITY or BUILD-TRIAGE priority; one adds a lint candidate.

## Evidence
- B1133 (UXS1): global response security headers are applied by `TridiumSecurityFilter` (`web-rt/…/filters/TridiumSecurityFilter.java:24-26` — wraps the response, calls `webService.getHttpHeaderProviders().applyHeaders()` BEFORE `chain.doFilter`), and that filter is installed on `/*` of EVERY servlet context via `configureNiagaraWebApp()` — the main webapp (`jetty-rt/…/BJettyWebServer.java:1141`) AND each custom `BWebServlet` (`:1460,1468`). A custom `/api/` servlet therefore receives the station's configured header providers with no per-servlet wiring; a servlet may override via `resp.setHeader()` in its body (the wrapper is unlocked). `[ev: corpus B1133]`
- B1134 (UXS4): `BGenericHttpHeaderProvider` can inject an arbitrary header — `headerName`/`headerValue` are unconstrained `BString` slots and `applyHeaders()` does `resp.addHeader`/`setHeader` (`web-rt/…/http/BGenericHttpHeaderProvider.java:52-54,96-103`) — so a static `Access-Control-Allow-Origin` is set by adding one under `WebService/httpHeaderProviders`. `BProfileFilterFactory` (custom servlet Filter) is CLOSED to third parties by a hard-coded 2-entry allowlist (`web-rt/…/BProfileFilterFactory.java:17-18,31-32`; enforced at `BJettyWebServer.java:474-478`). Dynamic per-request Origin reflection must be done in the servlet body. `[ev: corpus B1134]`
- B1135 (BLD7): signing-alias-absent behavior is PROFILE-TYPE-DEPENDENT (bytecode-corroborated in `niagara-plugins-7.6.17.jar`): profile FILE missing → `ProfileNotFoundException` → BUILD FAILS; alias missing under `LocalSigningProfile` (dev default) → `generateCert()` auto-creates a self-signed dev cert → build SUCCEEDS with a SIGNED-but-UNTRUSTED jar (which then fails at station load per BLD1/B1117); alias missing under `RestrictedSigningProfile` (CI/release) → `IllegalArgumentException` → BUILD FAILS; no aliases + `requireSigning=false` (default) → UNSIGNED jar, build succeeds. `[ev: corpus B1135]`
- B1136 (RUN5): `configFatal()` sets a permanent fault — `configOk()` clears `configFault` but returns early before `fatalFault` (`driver-rt/…/BDevice.java:425,431`), no code path resets `fatalFault`, `checkFatalFault()` short-circuits on restart-of-component (`BProxyExt.java:577-578`), and the `FATAL_FAULT` flag is "locked forever once started" (`:1134`) — cleared ONLY by a full station restart (javadoc `:459/:552`). Fatal causes = licensing failure + invalid parentage (`BDevice.java:412`). `configFail()`/`readFail()`/`writeFail()` are transient (cleared by `configOk()`/`readOk()`/`writeOk()`). A fatalFault point is permanently unoperational (tuning stops); a configFail point stays scheduled. `[ev: corpus B1136]`
- B1137 (PER1): there is NO framework prune-orphans utility for dynamic slots — enumerate via `getDynamicPropertiesArray()` (`baja/…/BComplex.java:606`, a safe snapshot) and `remove(Property/String)` (`BComponent.java:957,949`; frozen → `FrozenSlotException`), `removeAll()` (`:976`) removes ALL dynamic not selectively. Non-transient dynamic slots persist in the `.bog` and re-instantiate every station start (`Flags.TRANSIENT=0x00000002`, `Flags.java:184,389`), so orphans accumulate silently in the `DynamicTable` (memory/BOG bloat, no error). `[ev: corpus B1137]`
- B1138 (PER4): a worked `started()` self-migration recipe (closes B754-G2) — detect an orphan by name with `getProperty(name)` (null if absent, `BComplex.java:527`), guard on `isDynamic()` (`Slot.java:59`), read with `get(orphan)` (`:666`), copy into the new frozen slot with `set(...)` (`:854`), remove with `remove(orphan)` (`BComponent.java:957`); idempotent because `getProperty` returns null after the first run (B1121: started() runs every enable cycle); batch form must snapshot `getDynamicPropertiesArray()` FIRST (never remove during a live cursor — the framework's own `removeAll()` :976-986 is the pattern). `[ev: corpus B1138]`
- B1139 (PER7): recovering a station stuck at boot with a bad/wrong-version module is a PLATFORM-level Software Manager operation done while the station is DOWN (the platform daemon is up) — connect Platform node → Software Manager (`platDaemon-SoftwareManager.txt:25`); the module shows as "Bad Target" (bad manifest/unusable, `:75`) or "Out of Date"; remediate with Downgrade (`:117`, replace newer-with-lower), Uninstall (`:123`, no dependents), Import+Re-Install, or Rebuild Module Signatures (`:108`, station-not-running — repairs the B1117/B1135 trust failure), then Commit (`:127`). Never use the File Transfer Client for modules (`aFileTransferClient.txt:23` — profiles/signatures not applied). `[ev: corpus B1139]`

## Lessons
- **SECURITY (2):** Δ2 (PD-MH-UXS4) is the actionable CORS answer — the framework blocks the "obvious" custom-Filter approach, so the supported path is a BOG header provider (static) or servlet-body code (dynamic); Δ1 (PD-MH-UXS1) refines the existing header-hygiene deltas (A1/PD-ODA1): the framework already applies configured headers to custom servlets, so the servlet-level lint is a fallback layer, not the primary control.
- **BUILD-TRIAGE (1):** Δ3 (PD-MH-BLD7) is the highest-value new finding — a broken signing alias on a DEV profile does not fail the build; it ships a jar that dies at the station with an untrusted-cert ValidationException (BLD1). This is the deferred-failure trap the kit should warn about; pairs directly with the existing PD-MH-BLD1 triage delta.
- **DRIVER-CORRECTNESS (1):** Δ4 (PD-MH-RUN5) — the configFatal permanence is easy to misuse: a driver that calls `configFatal()` on a transient condition bricks the point until a station restart. The reference card makes the fatal-vs-transient choice explicit for driver authors.
- **RESOURCE/PERSISTENCE (1):** Δ5 (PD-MH-PER1) — orphan dynamic slots are a silent-bloat failure with no framework cleanup; the `dynamic-slot-orphan-prune` lint candidate is the actionable addition, complementing the schema-evolution guidance.
- **SCHEMA-EVOLUTION (1):** Δ6 (PD-MH-PER4) is the applied companion to Δ5 — the worked `started()` migration recipe closes B754-G2; fold the two together (PER1 rule + PER4 recipe) into the schema-evolution section.
- **BOOT-RECOVERY (1):** Δ7 (PD-MH-PER7) gives the operator runbook for a station bricked by a bad module — it is the delivery-side counterpart to the BLD1/BLD7 build-side triage; the "never File Transfer Client for modules" warning is the key gotcha.
- Highest-priority flagged: **Δ3** (BUILD-TRIAGE, deferred load-time failure), **Δ2** (SECURITY, CORS recipe), **Δ7** (BOOT-RECOVERY runbook), **Δ5** (RESOURCE, lint candidate).
