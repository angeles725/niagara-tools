**Delta count**: 5

## What happened
The ORD/BQL deck and the BQL Reference teach call-side rules the kit's consumer pattern breaks: the kit's own example
(`types/logic-authoring.md:191-200`) resolves a BQL ORD with `.get(Sys.getStation())` and no Context, closes the cursor
by hand, and is silent on subscription, record reuse and remote ORDs. The driver deck and Lab 11 teach the NDriver
framework (wizard, `NMessage`/`LinkMessage`, network worker), which the kit's driver guide never names — it documents the
`BBasicNetwork`/`Comm` stack only (`types/driver-authoring.md:89-118`) — and the corpus code review of the lab driver
found correlation, subscription and parsing defects a production driver must avoid. Lab 10 and RA2 add file-export
traps (`BajaFileUtil.createFile` vs `createFileToOverwrite`, `BOrd.DEFAULT`, platform charset).

## Evidence

- Kit example without Context / with manual close — `[ev: code types/logic-authoring.md:191-204]`; null-context lint covers writes only — `[ev: corpus B1242 §1242.7 K7]`
- BQL text is slot-unescaped first (`$20` matches with `'%$2420%'`); enum literals use the frozen-enum dot form (`alarm:SourceState.offnormal`); bound alarm scans with `FROM openAlarms` / BQLTIME — `[ev: corpus B1237 §1237.6]` `[ev: corpus B1242 §1242.3 rules 62-63]`
- ORD calls: resolve against the narrowest base; `resolve()` + `canRead()` when permissions matter, `get()` only deliberately; custom `BOrdScheme` throws `UnresolvedException` and tolerates unmounted components — `[ev: corpus B1237 §1237.3]`
- NDriver: wizard; one `NMessage` per message type, one `LinkMessage` for framing; override `doPing`/`doPoll` (threaded for you); post proxy-ext I/O to the network worker and return `true` from `write()`; subscription-driven polling — `[ev: corpus B1239 §1239.13]` `[ev: course Labs/Lab11 NDriver]`; defects: tagless protocol with the default 32 outstanding transactions from ≥3 threads, `private static final Set<String> subscribedPoints`, no bounds check in `LinkMessage.receive`, error flags ignored → NPE, every frame logged at INFO, unguarded proxy-ext casts, default timeout 1 s / 0 retries — `[ev: corpus B1239 §1239.12]` `[ev: course Labs/Lab11 NDriver/4 Reading and Writing Points/BTrafficLightDriverDevice.java]`; kit grep `NDriver`/`NMessage`/`getMaxOutstandingTransactions`/`getTag()` → 0 — `[ev: code types/driver-authoring.md]`

## Lessons
- A kit example is copied more often than a rule is read; the BQL example must carry the Context and try-with-resources itself.
- BQL is a snapshot read, not a subscription; proxy values it returns can be stale unless leased.
- A tagless request/response driver needs `maxOutstandingTransactions = 1` from the first commit; the framework default allows 32.
