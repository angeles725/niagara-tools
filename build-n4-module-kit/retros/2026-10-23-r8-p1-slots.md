## What happened
The course retro said `get(name) != null` "throws `NoSuchSlotException`" for an action name, quoting the javadoc. The
4.14.0.162 body behind `BComplex.get(String)` casts the slot to `Property`, so the exception that build raises is a
cast failure, not the documented one. Writing the rule as "catch X" would be wrong for one of the two readings;
writing it as "test with `getSlot(name) != null`" is right for both. The same unit refined a register premise:
READONLY is not checked by `set()` but is checked by `OrdTarget`-based `canWrite`.
