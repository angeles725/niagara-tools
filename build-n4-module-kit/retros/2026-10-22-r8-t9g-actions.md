## What happened
Folding the action, lexicon and palette items showed the kit's own checkers accepting forms the framework never
reads. `slot-coverage.sh` counted a `Type.slot` key as covering slot `slot` and a bare `<Type>=` key as covering the
type, so a lexicon passed while Workbench showed `toFriendly` text; `generate-wiring-map.sh` even preferred the
dotted key. `verify-module.sh` counted palette entries by the literal `<p n=` and so reported a Workbench-saved
palette (`n=` last) as empty, while it never looked at the `t=` type spec the BOG decoder rejects. The action
handler premise was also re-checked: the register's "type-load error" is right, and the kit's own example handler
was package-private, which the introspector rejects too.
